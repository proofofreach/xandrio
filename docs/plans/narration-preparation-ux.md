## Implementation boundaries

1. Book narration preference in the existing atomic settings store: `bookNarration[bookId] = { voiceId, fallbackPolicy }`. `fallbackPolicy` is `wait` or `instant`; new prepared book selections default to wait, so a narrator cannot change silently. Existing uncustomized books inherit the library default. Settings voice changes keep explicit “Default voice” scope. Player picker changes the current book. Selection and policy endpoints validate known book/allowed voice, preserve current authorization (admin voice changes), and reject known-uninstalled models. Disabled providers preserve saved preferences and completed audio.
2. Thread book identity explicitly through narration resolution. Extend `getActiveVoice(bookId)`, prepared/fallback helpers and `ttsForTier(tier, bookId)`; return fixed-variant workers for book-specific voices. Update playback orchestrator dependencies and chapter/stream/download/prefetch contexts so concurrent books never mutate a global voice to render. Include actual `voiceId` in playback responses and show the audible narrator separately from the requested book narrator. Requests with an explicit tier keep their established contract; default prepared routing obeys the saved fallback choice.
3. Make premium preparation use a fixed-variant worker from the start. One selected narrator job per book, independent of other books and library-default changes. Preserve completed chunks. Pause/Resume is durable; automatic chapter opens cannot resume a user-paused job. Pause releases only the background consumer/claim, never a foreground playback consumer. Disabled/offline states preserve intent. List paused/error jobs in Audio Activity, with narrator and ready time; retain existing ordering and offline/download cancellation behavior.
4. Readiness is completed chapter audio, never just chunks. Compute contiguous ready audio from the current chapter/offset to the first gap, divide by current playback speed, and label the scope. Use measured chapter durations when available; mark estimates explicitly otherwise. Whole-book count remains secondary. Add honest waiting/paused/offline/reconnecting states. ETA is shown only if recent measured work for this voice supports it and is not currently paused/offline; unknown means no invented countdown.
5. Native selection buttons in both voice pickers, distinct Preview/Save controls, full focus treatment. Name the choice and scope clearly. Wrap phone status text and use 45px minimum interactive targets. Open voice sheet immediately, render pending refresh, and prevent stale responses from crossing book/voice changes. Initial preparation state is “Checking preparation…”; later polling failures preserve old data with a reconnecting indication. Update offline cache version and expected version together.
6. Update DESIGN.md/PRODUCT.md narrowly for the accepted book-narration contract. Document optional worker deployment and preserve the app's rollback path. Feature and report changes only in commits.

## Failure scenarios — recorded before implementation

- Two books have different narrators; concurrent manifests, chunks, audio streams, lookahead, downloads or worker restart use the wrong global voice/cache key.
- A library default change silently replaces an explicitly chosen book narrator or stops its job.
- An unready prepared chapter silently plays a different narrator despite wait policy, or a saved instant choice does not work after reload. Switching policy while listening loses position or swaps mid-word.
- 7/8 ready includes a gap in chapter2; UI claims a long continuous buffer. Seeking or changing speed leaves old ready minutes; estimated durations appear measured.
- Paused work auto-resumes on chapter open or process restart; canceling background work cancels foreground playback; a stale promise removes a newer job/journal.
- Missing/disabled models erase preferences or caches, start repeated failed generation, or render wrong available state.
- A stale book/voice response labels current audio incorrectly; status load failure looks idle; rapid picker taps leave competing requests.
- Keyboard cannot select/escape; nested option/button semantics fail; narrow phone controls truncate state or have small touch areas.
- Audio Activity duplicates a job already in the chunk queue, hides paused jobs, breaks ordering, or exposes another user's library jobs.
- Full-book Nano generation leaks memory, produces invalid/truncated audio, cannot resume safely, or harms current web/Kokoro health.
- Release includes unrelated state/weights/secrets, triggers paid private Actions, deploys a revision other than the protected public merge, or claims success without the production receipt.
